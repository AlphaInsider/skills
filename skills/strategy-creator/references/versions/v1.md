## 1.0.0

### Upgrade requirements

This release introduces the shared `contract_version` marker and generated
project version-maintenance guidance. For a legacy `0.0.0` project, add the
marker to `docs/plan.md` and add the installed-version workflow to an
attributable `AGENTS.md` as part of the combined target upgrade. This increment
does not require runtime-code, test, dependency, or generated `README.md`
changes.

### Verification

Confirm that the final plan uses the installed target version and that the
generated project guidance preserves the marker until the complete approved
upgrade passes.

## 1.1.0

### Upgrade requirements

This release adds the AlphaInsider target-source, creation, access,
description, and synchronization fields to `docs/plan.md`. It also adds the
documented API-permission bundle and remote-description maintenance rules to
attributable `README.md` and `AGENTS.md` files.

For a version-only upgrade, classify the configured target as an existing
strategy, preserve its remote metadata, and do not create a strategy or sync
its description. Remote description synchronization begins only after the
user confirms a behavior plan containing the exact description. The upgrade
alone does not require runtime-code or dependency changes.

### Verification

Confirm that the plan and attributable documentation contain the installed
target-management contract. Confirm that a version-only upgrade neither
created a strategy nor synchronized its remote description.

## 1.2.0

### Upgrade requirements

This release adds the optional continuous WebSocket recovery contract without
adding plan fields. For a project that uses WebSockets, audit the existing
confirmed retry and recovery behavior before changing runtime code. Pass
`reconnect=True` to `stream_events` when the plan requires continuous
reconnection and re-subscription; retain the default one-session behavior when
the plan requires the strategy to stop on a stream error. If the existing plan
does not decide between those behaviors, return it to `draft` and confirm that
missing decision before implementation.

Projects that do not use WebSockets need no runtime change for this increment.
For WebSocket projects, inventory and approval-gate replacement of the copied
`strategy/alphainsider_stream.py` and any caller change under the combined
target audit.

### Verification

Confirm that the helper, caller, documentation, and tests match the confirmed
recovery behavior before advancing `contract_version`.
