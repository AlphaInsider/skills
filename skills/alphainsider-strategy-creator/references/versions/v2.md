## 2.0.0

### Upgrade requirements

This release replaces the operation-mode values `native user-system` and
`agent scheduled task` with `background process` and `agent scheduler`. The
current contract accepts only `foreground`, `background process`, and
`agent scheduler`. Old values are stale. Do not keep them and do not silently
map them.

For an **update**, return the active plan to `draft`. Rewrite
`## Operation and scheduling` onto the current template fields and family
values. Re-run host and agent-tool discovery. Present all three families with
usable or not-usable results and recorded limitations. Interview only
Operation and scheduling, plus dependents if the runner choice changes
implementation commands or generated docs. Preserve every unrelated settled
decision.

Inventory exact `docs/plan.md`, `README.md`, and `AGENTS.md` rewrites. If the
user keeps an already-installed runner, record docs-only updates and leave
that runner untouched. If they change runner, record the normal pause,
disable, delete, and create actions. Never start or trigger a run. One
complete-plan confirmation authorizes that inventory. Then rewrite the plan
and generated docs, apply any confirmed runner changes, and set
`contract_version` to `2.0.0`.

A version-only confirmation performs no remote, process, scheduler, or
trading action unless the confirmed inventory records that exact action. A
**replace** starts on `2.0.0` and leaves the outgoing project unchanged while
drafting. A **retire** does not rewrite operation onto the new families.

Always present `foreground` as selectable. Present `background process` as
selectable only when this host has a supported user-level systemd, launchd,
or Windows Task Scheduler runner that still passes the native safety gates.
Present `agent scheduler` whenever any future-invocation tool exists, and
treat it as selectable for a recurring cadence when that tool can fire more
than once until paused or deleted, including session-scoped, time-limited,
and conversation-attached automations. Inspect this agent's own scheduler
and automation tools. Vendor-neutral text means do not name a product; it
does not mean skip those tools. Former agent-scheduler independence, access,
history, timezone, expiry, and scheduler-level overlap checks are recorded
limitations, not reasons to hide the family. After the user selects an agent
scheduler, create the task even when project access, runtime, or durability
is missing. Never put secrets in the task. A created task object may mark
the plan `implemented`. Local-only targets still create nothing and stay
`confirmed`. Failed required background-process installation stays
`confirmed`.

Recommend a compatible `background process` runner before an
`agent scheduler`. Keep `foreground` available. Ask Initial activation and
autostart for every invocation model. Recommend active for a first-session
ready target. Never trigger a run during build or verification. After
`implemented`, honor `active` autostart and an explicit later chat request.

This release also makes Strategy Creator independent of `alphainsider-api`.
Start requires only this skill's three scripts. Live target setup uses
`scripts/alphainsider_setup_request.py`, never copied API-skill helpers. New
and replacement projects write a project-local AlphaInsider client and
record the HTTP library as an agent default. Leave existing copied helpers
in place unless the confirmed Implementation inventory already records those
paths. When `alphainsider-api` is installed, read it for API behavior;
otherwise read the live AlphaInsider docs. Public strategy IDs may be shown.
Hide the API key, broker secrets, and webhook `api_token`.

This release also changes the run rule. Generated `AGENTS.md` must not treat
every live run as forbidden. On update, rewrite `AGENTS.md` and interview
Initial activation and autostart if that field is missing or still marked
not applicable for unmanaged foreground. The upgrade itself starts no
strategy unless the confirmed inventory records that exact action or the
user later explicitly asks to run.

### Verification

Confirm the three families are always listed, old operation-mode values are
not accepted, and the agent restructures the plan and generated docs after
one complete-plan confirmation. Confirm agent-owned repeating tools are a
selectable agent scheduler, former agent-scheduler checks are recorded not
used to hide the family, background-process gates are unchanged, native
installs still fail closed, a created agent-scheduler task may implement the
plan, and the upgrade itself creates, updates, pauses, disables, starts, or
deletes no operational resource unless the confirmed inventory records that
action. Confirm Strategy Creator starts without `alphainsider-api`, uses the
setup wrapper for target setup, and does not copy API-skill scripts into new
or replacement projects. Confirm agents refuse runs during build and
verification, honor `active` autostart after `implemented`, and honor an
explicit later chat request for `implemented`, `local-only`, or `retired`
projects.
